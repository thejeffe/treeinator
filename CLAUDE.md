# Treeinator

A front-yard "light cone" Christmas tree driven by individually addressable pixels, plus the software that runs it. Drawing package GP-TRE-001 (Golden Pecan). This file briefs Claude Code on where the project stands; read it first, then `tree-show/README.md`.

## What we are doing now

Running **tree-show** (the show server in `tree-show/`) on this server so it plays designs and playlists to the tree all night with no phone open. This install: Debian 13, port 8100 (signinator uses 8080), served at the tree-show HTTPS name (see Caddy); WLED controller is the tree's WLED host (its IP); `WLED_HOST` uses the DNS name. The original target is a Proxmox LXC (Debian 12) or any Debian/Ubuntu box with systemd. Docker files exist but are optional.

First steps for a new session:

1. Read `tree-show/README.md` and skim `tree-show/server.js` and `tree-show/public/engine.js`.
2. Check the box: `node --version` (needs 18+), `systemctl` available, the WLED controller's IP is reachable (`ping`), UDP 4048 outbound allowed.
3. Install: `cd tree-show && sudo bash install.sh <WLED_IP>`. It installs Node if missing, copies to `/opt/tree-show`, writes `/etc/tree-show.env`, data in `/var/lib/tree-show/shows.json`, and enables `tree-show.service`.
4. Verify: `curl -s localhost:8080/health`, `journalctl -u tree-show -f`, then open `http://<server-ip>:8080` from a phone.
5. With WLED reachable, press **Play on tree** in the Shows view and confirm frames arrive (WLED's info page shows live FPS).

Ask before changing the pixel order, the network/ports, or anything under `/etc`.

## Hardware (fixed decisions)

- **Tree:** 19 vertical pixel strips (resized from 20 on 2026-11-07) over a 270° arc (open back faces the house), Ø48" base ring, Ø14" hub at 102", overall 127" with topper. Each strip is a 30 mm black HDPE pixel mounting strip (1" hole pitch) holding one 50-pixel string in every other hole (2" pitch), screwed to the hub top at the upper end and wrapped/screwed to the ½" PVC ring at the bottom.
- **Topper:** Ø22" disc with 4 concentric rings of 10/20/30/40 pixels (100 total), every ring starts at 12 o'clock, so a five-point star lands on pixels in every ring.
- **Pixels:** 12 mm WS2811-type bullet pixels, 5 V, 1,050 total (950 tree + 100 topper).
- **Controller:** custom ESP32-WROOM-32E board running WLED (74HCT125 level shifter, 4 outputs, 20 A).

| WLED output | GPIO | Carries | Length | Start |
|---|---|---|---|---|
| LED1 | 16 | Tree ribs 1–10 | 500 | 0 |
| LED2 | 17 | Tree ribs 11–19 (450 pixels; WLED 950–999 unused) | 500 | 500 |
| LED3 | 18 | Topper | 100 | 1000 |
| LED4 | 19 | Spare | — | — |

WLED: enable UDP realtime (DDP on port 4048); current limiter at or below the supply rating (board max 20,000 mA).

## Pixel order (do not change without asking)

- WLED index 0–949: tree serpentine starting at the **bottom of rib 1** (leftmost seen from the street). Rib 1 runs up, rib 2 down, rib 3 up … rib 19 ends top right. WLED 950–999 are sent black. Odd ribs take data at the bottom, even ribs at the top.
- WLED index 1000–1099: topper, center ring outward (10, 20, 30, 40), each ring from 12 o'clock clockwise seen from the street.
- Internal order in `engine.js` is `k = rib*50 + row` (row 0 = top), then the topper (N = 1050); `WIDX` / `toWled()` converts to WLED order in a WN = 1100 pixel frame. Rib count, pixels per rib, arc and topper start come from the Settings screen (defaults in `DEFAULT_CONFIG` in `engine.js`).
- The controller now has a WLED **2D matrix** (19 wide x 50 tall, two vertical panels) with realtime "respect LED maps" on, so tree-show must use **WLED mapping = 2D matrix**: it sends row-major from the top-left (`y*ribs + x`) and WLED applies the wiring. Strip order (serpentine above) is only right when WLED has no matrix or ignores LED maps.
- **Text deskew** (setting, 0–100%, default 100): the Text pattern measures letter columns by distance around the cone (rib offset from the center rib x cone width at that height, `textX()` in `engine.js`), so letters don't fan out where ribs converge near the top. Scroll speed is in text columns, so it's the same physical speed at every height.
- WLED's realtime gamma correction is off (`no-gc`), so tree-show applies gamma (setting, default 2.8) to WLED output; without it dim backgrounds glow visibly.

## Software

```
phone (mixer page) --HTTP/WebSocket--> tree-show (Node, port 8080) --DDP UDP 4048--> WLED (ESP32)
```

- `tree-show/server.js` — HTTP + WebSocket server. Stores designs/playlist in `DATA_DIR/shows.json`, runs the playlist loop at `FPS` (40) and sends DDP (3 packets per frame, push flag on the last). Live frames from the page override the playlist for 1.5 s after the last frame. Broadcasts status every second; streams a 20 fps preview to pages that "watch".
- `tree-show/public/engine.js` — shared by browser and server (UMD). Geometry, 38 patterns (incl. 10 WLED-style effects: Soap, Rockets, Starburst, Pacifica, Matrix, DNA, Rain, Lightning, Bounce, Lava — own implementations, not WLED code; they use per-pixel `X`/`Y` positions in 2" pixel spacings), palettes, `render(look, run, dt, out)`, `randomLook()`, `Player` (in order / shuffle / random, crossfade), WLED ordering, and the 99-design `LIBRARY` in 11 categories (incl. "WLED-style effects"). `mergeLibrary()` adds new library designs to existing data without restoring ones the user deleted (`db.removed`).
- `tree-show/public/index.html` — one-screen mixer page. **Mix** view: two decks, crossfader, tempo/tap, pads, topper modes, image upload, Save design, Go live. **Shows** view: playlist editor, designs grouped by category, Play on tree, Preview. Written as an HTML fragment; the server wraps it in a document shell when serving. Falls back to browser localStorage when not served by tree-show.
- **Hold on tree**: `POST /api/player {action:'design', design, hold:true}` keeps that design on the tree indefinitely (stored in `db.playlist.hold`, survives restarts); `release`, `next`, `play` or `stop` clears it. UI: **On tree** button on each design row (renamed from Hold at the owner's request); Next becomes **↩ Playlist** while a design is held; status reads "Staying on tree: …".
- **Shows is the main screen** (the mixer is secondary, "Mixer" tab). **Edit** on a design opens a dialog (`openEditor`) with its own preview canvas: name, category, pattern + colors + speed + text, second pattern (off / blend / alternate every N beats), tempo, topper mode and colors; Save (in place), Save as new, Open in mixer; "Show on tree while editing" holds the edited design on the tree (released on close). Saving a design that's playing or held updates it on the tree immediately.
- **Named playlists**: `db.playlists=[{id,name,items,mode,fade,randSec}]`, `db.activeId` = the one the tree plays; `db.playlist` is player state plus a copy of the active one (`syncActive()`). API `PUT|DELETE /api/playlists/:id`, `POST /api/player {action:'play', playlist:id}`; legacy `PUT /api/playlist` edits the active one. The page remembers which playlist you're looking at (localStorage `treeSelPl`); Play on tree plays that one. Schedule entries use `what: 'playlist:<id>'`. A playlist the schedule uses can't be deleted.
- **Calibration** (Settings → Calibrate LED mapping): test patterns (one rib, all ribs colored, one row, halves, one pixel, topper rings, dim white, off) sent from the page over the live channel through `E.toWled`, so the real mapping is exercised; preview is a flat unrolled grid.
- **WLED setup button** (`POST /api/wled/setup`): sets WLED `def` to `{ps:0, on:false}` (boots off, no boot preset) and its segments to solid black, and sets `settings.wledBlank` so tree-show re-applies solid black whenever it turns WLED on; when DDP stops, WLED falls back to black. Saving a WLED preset via `psave` didn't work on WLED 16 while it was receiving realtime, hence this approach. Done on the real controller 2026-11-07 (it was booting preset 1 "Soap", on).
- **General brightness**: `db.bright` (0.05–1, `PUT /api/brightness`), applied in `sendDDP` to everything sent (playlist, hold, live mixer). Replaced the old playlist-only `playlist.bright` (migrated once).
- **Schedule**: `db.schedule = {enabled, entries:[{days:[0-6], start, end, what:'playlist'|'design:<id>'}]}` (`GET|PUT /api/schedule`), server local time (America/Los_Angeles). Overnight windows allowed; design windows beat playlist windows; outside every window the tree is off. Edge-triggered every 15 s, so manual Play/Stop/Hold sticks until the next change.
- **Sun times in the schedule**: a start/end is `'HH:MM'` or `sunrise|sunset|dawn|dusk` with an optional minute offset (`'dusk+30'`, `'sunset-60'`, max ±360). Dawn/dusk = civil twilight (96°). Needs `db.schedule.lat/lon` (dialog has fields + Use my location). `sunEvent()` in server.js (Almanac for Computers sunrise equation; checked against Los Angeles within ~2 min, DST-aware). Resolved per day; overnight windows check yesterday's times.
- **Dated schedule times**: an entry can have `date: 'YYYY-MM-DD'` (+ `yearly: true` to match month-day every year) instead of weekly `days`. While any dated entry is active it beats the weekly ones (`scheduleWant`); then design beats playlist as before.
- **Classic colors** (deck `cl`): patterns marked `cl: 1` in `PATS` (Rainbow, Bulbs, Ornaments, Fireworks, Confetti and the multicolor WLED-style effects) use their own palettes unless `cl === false`, which `render()` passes as `c.mono`; then `mc()`/`rp()`/`monoPal()` give shades between the design's colors. Unset = classic (Bulbs: classic if color 2 is white, for older designs). Editor shows a Classic colors checkbox for those patterns.
- **Names**: the app is "Treeinator" (page title, h1, home-screen name); the mixer view is called **Sir Mix-a-Lot** in the UI (`data-v="mix"` internally). GO LIVE is a big button in its own box (`.livebox`, `#stream`, label via `liveLabel()`).
- **Home-screen app**: `PAGE_HEAD` in server.js carries the manifest (`public/manifest.webmanifest`), `apple-touch-icon` (`icon-180.png`) and Apple standalone tags; icons `icon.svg`, `icon-180/192/512.png` (rendered from the SVG with headless Chromium). No service worker.
- **DJ booth (Mixer view)**: `body.booth` dark theme; each deck has a monitor canvas rendering that deck alone (same run times, dt 0), a level meter, a beat LED and an ON AIR lamp scaled by the crossfader share; the stage is the master (mix + pads), tagged ON AIR → TREE with a red glow while live.
- **Thanksgiving effects**: `leaves`, `wind`, `harvestmoon`, `turkeytail` (palette `AUT`). **Retro graphics**: `GFX` in engine.js holds original 1-bit-style pixel art (letters map to `GPAL` colors), sets in `GSETS` (fall, holiday, newyear, all). Patterns `graphic` (one picture on the front, cycling through a set every 8 beats) and `parade` (scrolling); deck field `g` = graphic id or set name; deskewed like text. These are our own drawings, not copies of any commercial clip art.
- **Library playlists**: `LIBRARY_PLAYLISTS` in engine.js ("Leading up to Thanksgiving", "After Christmas: New Year's"), merged into `db.playlists` at startup by `mergePlaylists`; deleting one records it in `db.removedPlaylists`.
- **Schedule date ranges**: dated entries take `date` and optional `dateTo`; with `yearly` the month-day range may wrap past New Year (`onDay`). **Conflicts**: `scheduleConflicts()` simulates the next 366 days in 15-minute steps and reports overlapping pairs (days, first time, winner, reason; `override` = dated vs weekly). `POST /api/schedule/check` checks an unsaved schedule; GET/PUT include `conflicts`.
- **Preview brightness**: the live view sent to pages uses `masterBright()^0.4`, because dim LEDs look much brighter to the eye than linear; at 5% the preview still shows the lights.
- **Playlist timing**: each playlist has `sec` (time per design, default 45); an item's own `sec` overrides it (the page shows the playlist time as a placeholder; typed values are highlighted). Old data was migrated (most common item time becomes the playlist's).
- **No surprise restarts**: Play for the playlist that's already playing, or the schedule asking for it again, keeps going (`alreadyPlaying`). In-order playlists remember their position in `db.positions` (`rememberPos`) and resume after it via `Player.start(pos)`. (Before this, every Play press or schedule save restarted at the first design, which is why it kept going back to Falling leaves.)
- **USC / UCLA**: Team colors category has USC (cardinal #990000, gold #ffcc00) and UCLA (blue #2774ae, gold #ffd100) designs, Crosstown rivalry and Game day parade (graphics `football`, `trophy`; set `gameday`). Team colors and words only, no logos. Library playlist "Game day: USC and UCLA" (`pl-gameday`).
- **Text fill**: deck `below` = a pattern drawn (at 70%) in the rows above/below the lettering, with a dark one-row gap (`textFill` in engine.js); unset = twinkle, `'none'` = plain. Not text/image/graphic/parade. Editor: "Below the text".
- **Only this design's colors** (`look.strict`): `render()` snaps every pixel to the nearest of the design's colors (both decks + topper colors, ignoring near-black) at the pixel's brightness (`strictPal`/`snapColor`). All USC/UCLA designs and Crosstown rivalry use it, so they never show anything but team colors. Editor checkbox under Design.
- **Library design versions**: a library design can carry `v`; `mergeLibrary` replaces an older copy unless the person edited it (`edited: true` is set on every design saved from the page). Library playlists also pick up newly added library designs once (`db.plOffered`).
- **Categories (by season)**: `CAT_ORDER` (exported as `E.CATS`, which the page sorts by): Thanksgiving and fall; Christmas · classic / candy and sweets / Santa's workshop / holy night / messages / party / effects / retro graphics; Winter · snow and ice / fireside; New Year's; Team colors; Effects; Party and everyday. `CATS` is still indexed by L()'s number; `MOVE` reassigns designs to the right section; `OLD_CATS` renames older category names on saved designs; `RETIRED` drops duplicates (unedited copies, and from playlists). Unedited library copies keep their name and category in step with the library.
- **No strobe effects in designs and shows** (owner's request): "Lightning storm" design retired; Pulse is a smooth swell every two beats. Keep new library patterns free of whole-tree flashing (small frame-to-frame brightness changes). Strobe-like effects live only in Sir Mix-a-Lot (see below).
- **Schedule priority = list order** (↑ ↓ in the dialog): the highest active time wins (`scheduleWant`). Older schedules were sorted once to keep their old behavior (dated > weekly, design > playlist; `schedule.ordered`). `scheduleConflicts` reports overlaps (higher one wins) and times that never play (covered or no days in the next year). `schedulePlan(sc, 30)` gives day-by-day blocks for the "What will play" summary (sun-time boundaries carry their spec and exact time). The "Run the tree on this schedule" box must be on for any of it to act.
- **Sir Mix-a-Lot keeps its strobe tools** (owner asked for them back): Flash/Strobe/Black/Invert pads are instant, and decks have mixer-only patterns (`mix: 1`) Lightning and Beat flash. Mixer-only patterns are left out of the design editor (unless a design already uses one), random looks, text fill and the library, so shows that run on their own stay strobe-free.
- **Mode badge** (`#modeBadge`, top of the page on every view: grid area `mode` between the title and the view buttons on wide screens, above them on phones; opens the schedule). Compact: a chip plus one short line, "what's happening · when it changes", clamped to 2 lines (3 on phones under 520px, where ON SCHEDULE shows as SCHED). Times are plain clock times via `whenShort`. The full sentence, with sun times, is in the `title` tooltip. States: OFFLINE; MANUAL (no schedule); ON SCHEDULE ("Christmas until 11 PM" / "Off until 4:52 PM → Thanksgiving"); OVERRIDE (stopped or playing by hand, says when the schedule comes back). Server `scheduleStatus()` adds `following`, `untilInfo`, `next` (from a 2-day `schedulePlan`, cached per minute).
- **Christmas effects** (Christmas · effects): `twinklelights`, `stringlights`, `ornamentdrop` (bounce physics `dropY`), `sleigh` (sleigh + reindeer + Rudolph + gold trail), `shootingstars`, `snowswirl`, `tinsel`, `ribbonwrap`, designs `x-cx-*`. All smooth (whole-tree brightness change per frame < 1%).
- **"Christmas" playlist**: the old "Main playlist" (id `main`) was renamed and filled from `CHRISTMAS_PLAYLIST` once at startup (`db.mainIsChristmas`), at the owner's request. Schedule entries pointing at `playlist:main` keep working.
- **Sir Mix-a-Lot Invert** swaps each deck's Color 1 and Color 2 (and the topper colors) while held (`swapped()`), instead of RGB inversion, so only the design's own colors show.
- **Sir Mix-a-Lot Swap** (`#swapBtn`, next to the crossfader): glides the crossfader to the other deck over ~1 s with easing (`M.swap`, `swapStep()` in the loop); pressing again mid-glide reverses; turns Auto off; dragging the slider cancels it.
- **Sir Mix-a-Lot Blackout toggle** (`#blackTgl`, key B): latches the master output to black (`M.blackout`) until tapped again; the Black pad still works only while held. Decks keep running underneath.
- **Phone scrolling in Sir Mix-a-Lot**: on phones (max-width 899px or max-height 519px) `.app[data-view="mix"] .ctrl` scrolls (overflow-y:auto), so the pads, topper and images are reachable.
- **Tree previews keep one shape**: `paint()` draws the tree in a fixed 200×350 box (`TREE_AR`=1.75), scaled evenly and centered, so no canvas can stretch it. The main stage, the deck monitors (re-sized when their box width changes, e.g. on a tab switch or rotation) and the design editor all size their canvases at 1.75. The calibration view is an unrolled grid, not a tree.
- **Resume schedule**: in the OVERRIDE state the mode badge shows a subtle accent-colored "↺ Resume" at its right end (owner wanted it subtle, not a button; just the ↺ icon on phones, where the OVERRIDE chip is hidden and the text starts "Override ·"). Tapping the badge then POSTs `/api/schedule/resume` (clears any live mixer, `lastWant=null`, `runSchedule(true)`) and stops this page's live, preview or try first. In the other states tapping still opens the schedule. It returns 409 if the schedule is off.
- **Sir Mix-a-Lot stage = what the tree really shows**: while this page isn't live, the big stage shows the live feed from tree-show (tag TREE · NOW), not the mix; the deck monitors show the decks. When live it shows your mix (● ON AIR → TREE). `updateWatch` watches on Shows and in the mixer whenever this page isn't live, if the tree is playing or someone else is live. The server forwards live-mixer frames to other watchers (`liveToView`: WLED order with gamma → tree order, every 2nd frame). On stop the page sends `{type:'unlive'}` so the playlist takes back over at once, without waiting out the 1.5 s hold.
- **Reload / version** (`#reloadBtn` ↻ next to ⚙): server.js computes `BUILD` (a sha1 of server.js, index.html and engine.js at startup), stamps `data-build` on `<body>`, adds `?v=BUILD` to config.js and engine.js, serves `/api/version`, and includes `build` in status. The button turns gold when the server build differs from the page's. Tapping it clears Cache Storage and service workers, then does `location.replace('?v=…&t=…')`. Every response is sent no-store/no-cache. tree-show keeps no server-side cache (files are read from disk on every request).
- **Pattern hints**: a pattern can carry `h` (help text) shown in the design editor. Bulbs: color 2 white = classic multicolor C9; else alternates color 2/color 1 (all color 2 if color 1 is black).
- **WLED power** (setting `wledPower`, default on): tree-show turns WLED off (`POST /json/state {on:false}`) while nothing is playing so it doesn't fall back to its own preset, and on again when playing.
- **Topper setting** (`topper`, default on): off means the topper isn't connected, so WLED frames stop at the tree (`WN = NT`), the topper isn't drawn in the preview, and the mixer's Topper box and Topper img button are hidden. Topper pixels are still rendered internally so designs keep their shape.
- **Text settings**: `textTop` (pixels from the top), `textSize` (pixels per font dot), `textWidth` (ribs per dot at the text's middle), plus `deskew`.
- **Colors when dim** (setting `dither = {mode, darkest}`, Settings → Colors when dim, applies live, no restart): `tree-show/dither.js` (server only; engine.js untouched). Without it, gamma is rounded to whole levels and then general brightness rounds again, so weak channels drop out and hues drift when dim. Modes: `off` (old behavior, default), `spatial` (4x4 ordered dither by rib/row, topper by ring index; steady), `hue` (one steady color per pixel chosen to keep its hue), `temporal` (per-pixel error carried frame to frame; needs a fast WLED refresh). Server frames are dimmed from floats in one step (`sendFrame`); live-mixer bytes are dimmed from their gamma'd bytes (`sendLive`); `sendDDP(bytes, prepared)` skips its own brightness pass for those. Same logic as Signinator's (`/opt/signinator/app/engine.py`). Measured at 10% brightness: average color-direction error off 2.0°, spatial 0.4°, hue 1.7°, temporal 0.1°; under 0.25 ms per frame. `dither.js` is copied by install.sh and tools/deploy.sh.
- **Dimming in WLED** (`dither.mode = 'wled'`, `dither.wledFps`): needs Jeff's WLED build (`thejeffe/WLED` tag `v16.0.1-dither1`, installed from Lickety Split; usermod "Temporal dither"). tree-show sends the plain picture (`ditherer.plainFrame`; live-mixer bytes un-gamma'd by `plainBytes`) and `syncWledDither()` posts `{dither:{on, bri16 (general brightness x 65535), g (layout gamma), wb, dark, fps}}` to WLED's /json/state, re-sending when the brightness changes or WLED forgets it (seen in /json/info `dither`). Other modes send `{dither:{on:false}}`.
- **Home Assistant** (setting `mqtt = {enabled, host, port, username, password, base, prefix}`, Settings → Home Asst.; the password is write-only, GET returns `passwordSet`): `tree-show/ha.js`, a built-in MQTT 3.1.1 client (QoS 0, no npm package) that announces the device "Treeinator" with one retained discovery message `homeassistant/device/<base>/config` and publishes retained states to `<base>/state/<key>` (checked every 2 s), commands on `<base>/cmd/<key>`, last will `<base>/status` = offline. Entities: light (play/stop + brightness 5–100%), playlist and hold-design selects, next and resume-schedule buttons, run-on-schedule switch, showing/mode/WLED-fps sensors, WLED connectivity, dimming select, auto-fps switch, max-fps number. HTTP and MQTT share `playerAction`, `setBright`, `resumeSchedule`, `setScheduleEnabled` and `applySettings` in server.js. Test against a fake broker, never the real HA one with test topics.
- **Frame rate follows WLED** (settings `fpsAuto` default on, `fpsMax` default 60; Settings → WLED → Frame rate; live, no restart): the frame loop reschedules itself at `currentFps()` (was a fixed `setInterval` at `FPS`). `pollWledFps()` reads WLED's `/json/info` every 8 s while the playlist is playing (not while live): if WLED shows < 90% of what's sent, settle at 95% of WLED's fps; otherwise probe at the max every 5 min (`FPS_PROBE_MS`); re-measure when WLED's LED count changes or it reboots; ignore readings for 6 s after a change. Patterns are clock-timed, so the rate never changes their speed. `GET /api/settings` includes `frameRate: {target, sending, wled}`. `WLED_HTTP` env overrides the address for `/json/info` (tests only). Same logic as Signinator's.
- **WLED links** (Settings → WLED, `wledLinks()`): "WLED main page" (`/`) and "WLED setup" (`/settings`) for the host typed in the field, opening in a new tab (owner wanted just these two). Signinator has the same.
- **Settings tabs**: WLED (controller + frame rate) · Layout (topper, ribs, rows, arc, topper start, mapping, flip, calibrate) · Color (gamma + colors when dim) · Text (deskew, position, height, width). Field ids unchanged; last tab remembered in localStorage `treeSetTab`.
- API: `GET /api/state`, `GET /health`, `PUT|DELETE /api/designs/:id`, `PUT /api/playlist`, `POST /api/player {action: play|stop|next|release|design}`, `POST /api/library/restore`, WebSocket `/ws`.
- Config via env (`/etc/tree-show.env`): `WLED_HOST`, `WLED_DDP_PORT`, `HTTP_PORT`, `FPS`, `DATA_DIR`. `WLED_HOST`/`WLED_DDP_PORT` are only starting defaults now.
- **Settings screen** (⚙ next to Mix/Shows): WLED host/port and tree layout (`ribs`, `rows` = pixels per rib, `arc` degrees, `topStart` = WLED index of the first topper pixel). Saved to `DATA_DIR/settings.json`, which overrides the env. Host/port apply immediately; a layout change makes the server exit so systemd restarts it (the engine builds its pixel map once at load), and the page reloads. The page gets the layout from `/config.js` (`window.TREE_CONFIG`) before `engine.js`; Node gets it from `global.TREE_CONFIG`. API: `GET|PUT /api/settings`, `GET /api/wled?host=` (reads the controller's `/json/info` + `/json/cfg` to show its LED outputs).

A design is `{id, name, cat, look}` where `look = {A:{p,c:[hex,hex],sp,text?}, B:{...}, xf, auto, bpm, top: star|flake|ripple|follow|image, tc?, img?}`. `img` is base64 of 1,050 RGB pixels in internal order.

## Conventions

- Keep `engine.js` dependency-free and working in both Node 18+ and the browser.
- Test the server against a fake WLED (a UDP listener on a spare port, `WLED_HOST=127.0.0.1 WLED_DDP_PORT=14048`) before pointing it at the real tree.
- After changing `engine.js`, restart the service: `sudo systemctl restart tree-show`.
- **Updating the running server**: after the next `sudo bash install.sh`, /opt/tree-show is owned by the user who ran it (jeff). From then on, make changes in `tree-show/`, run `tree-show/tools/deploy.sh` (no sudo: it syntax-checks and copies server.js, package.json and public into /opt/tree-show), and the owner runs `sudo systemctl restart tree-show`, the same as signinator. If package.json dependencies change, use install.sh instead (it runs npm install).
